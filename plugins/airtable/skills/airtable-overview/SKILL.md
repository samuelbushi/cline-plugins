# Airtable Overview

Use this skill to explain Airtable concepts before planning or changing a base.

## Core Model

- A workspace contains bases.
- A base is an application database for one workflow or operating area.
- Tables hold records.
- Fields define typed columns such as text, number, select, date, collaborator, attachment, formula, lookup, rollup, or linked records.
- Linked-record fields connect records across tables and enable rollups, lookups, and relational workflows.
- Views are saved ways to look at a table, such as grid, kanban, calendar, gallery, timeline, list, or form.
- Interfaces are user-facing app surfaces built on the same base data.
- Automations run actions when records change or schedules fire.

## Guidance

- Clarify whether the user wants to inspect an existing base, modify records, design schema, build an app surface, or automate a workflow.
- Ask before changing schema or records.
- Prefer typed fields and linked tables over freeform text when the data will be filtered, reported, rolled up, or used by agents later.
- Explain tradeoffs in plain language. Airtable is not just a spreadsheet; it is a relational app database with collaborative views and interfaces.
