# Buildkite Pipelines

Use this skill for `.buildkite/pipeline.yml` work.

## Basic Shape

```yaml
steps:
  - label: "Tests"
    command: "npm test"
    artifact_paths: "coverage/**/*"

  - wait

  - label: "Deploy"
    command: "scripts/deploy.sh"
    branches: "main"
```

Buildkite runs steps at the same level in parallel unless ordering is added with `wait` or `depends_on`.

## Step Types

| Type | Use For |
| --- | --- |
| `command` | run shell commands on an agent |
| `wait` | wait for previous parallel steps |
| `block` | require manual approval |
| `input` | collect form values |
| `trigger` | start another pipeline |
| `group` | organize related steps |

Prefer `depends_on` for specific dependency graphs and `wait` for broad phase boundaries.

## Defaults To Prefer

- Store the primary pipeline at `.buildkite/pipeline.yml`.
- Keep complex shell logic in checked-in scripts under `.buildkite/scripts/`.
- Pin plugin versions to full semver such as `docker#v5.13.0`.
- Use `artifact_paths` for declarative artifact upload.
- Use `buildkite-agent annotate` inside commands for rich failure summaries.
- Use `soft_fail` for advisory checks that should not block the build.
- Use `cancel_on_build_failing: true` for expensive parallel jobs when early failure should stop work.

## Variable Interpolation

Use `$VAR` for upload-time interpolation and `$$VAR` when the variable should be expanded by the agent at job runtime. This matters in dynamic pipelines generated by scripts.

## Dynamic Pipelines

Dynamic pipelines are useful when steps depend on changed files, generated test shards, or repository state.

```bash
scripts/generate-pipeline.sh | buildkite-agent pipeline upload
```

Validate generated YAML before upload when possible. Keep generated step keys stable so retries and dependencies remain predictable.

## Security Review

Before committing pipeline changes:

- Check that no secret value is embedded in YAML.
- Prefer Buildkite secrets or OIDC over static cloud credentials.
- Reject obfuscated shell, base64 command execution, and unexpected network exfiltration.
- Confirm deploy steps are gated by branch, approval, or environment where needed.
